# exchange-rate-service


Примеры корректных запросов сервису через curl:

// обновить котировку по паре валют (вернет ID для получения котировки)
curl -i -X POST "$BASE_URL/rates/updates" \
  -H "Content-Type: application/json" \
  -d '{"base":"EUR","quote":"MXN"}'

// запрос котировки по ID (подставить ID)
  curl -i "$BASE_URL/rates/updates/$ID"

// запрос последней успешнополученной котировки по паре валют
  curl -i "$BASE_URL/rates/latest/EUR/MXN"


  Допущения в проекте:
  Поле updated_at отражает момент успешного получения валютного курса нашим сервисом от внешнего провайдера, а не время фактического обновления котировки на стороне провайдера.
  Бесплатные внешние API могут обновлять котировки, например, раз в сутки. Если бы сервис присваивал timestamp от такого API в сервисный update_at - несколько запросов в течение дня могли бы возвращать одинаковое время обновления с одинаковой котировкой, что ненаглядно бы показывало работу сервиса.
  Сейчас два обновления могут вернуть одинаковый курс, но разные значения updated_at. Это нормально: фиксируется факт получения котировки в определённый момент, а не факт изменения самого курса.
